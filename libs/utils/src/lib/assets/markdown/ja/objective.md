# 目的

TagCheck は、トラッキングの問題を Google Analytics のレポートに影響が及ぶ前に検出することを目指しています。計画した各 GA4 イベントを実際のサイト上で毎回同じ方法でチェックするため、サイトのリリースや GTM の変更のたびにチェックを再実行できます。

## データレイヤーチェック

サイトは `window.dataLayer` にデータをプッシュし、GTM はそれを読み取ってタグに値を設定します。データレイヤーチェックは、テストのイベントのプッシュを見つけ、キーごとにスペックと比較します。次の場合に失敗します。

- イベントがまったくプッシュされない。
- スペックにあるキーがプッシュに含まれていない。
- 値がスペックと異なる、またはパターンに一致しない。
- e コマースイベントの前に `{ ecommerce: null }` がプッシュされていない。Google は、以前の e コマースデータをクリアするためにこのプッシュを行うよう求めています（[Tag Manager で e コマースを測定する](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce?client_type=gtm)）。

## リクエストチェック

プッシュが正しくても、GA4 のデータが正しいとは限りません。タグが発火しないこともあれば、別のプロパティに送信したり、GA4 が収集しない形式でパラメータを送信したりすることもあります。リクエストチェックは、実際にブラウザから送信される内容を確認します。プロジェクトの測定 ID に送信されたそのイベントの GA4 リクエストを傍受し、パラメータを `dataLayer` プッシュと同じ形のオブジェクトに再構成して、同じスペックと比較します。該当するリクエストが送信されない場合や、パラメータが一致しない場合に失敗します。

リクエストチェックには、**Project Information** に測定 ID が設定され、**Google Tag Manager** 設定で **Activate Request Check** がオンになっている必要があります。これらがない場合、実行ではデータレイヤーチェックのみが行われ、テストは最高でも Partial にしかなりません。

## ステータスの見方

- **Passed**: 両方のチェックに合格しました。
- **Partial**: 一方のチェックに合格しました。サイトは正しいデータをプッシュしているのにタグが計画どおりに送信していない可能性があり、その逆の可能性もあります。
- **Failed**: どちらのチェックにも合格しませんでした。まずデータレイヤーから確認してください。イベントがまったくプッシュされていない可能性があります。
- **Not run**: テストがまだ一度も実行されていないか、すべての実行が削除されています。

ステータスにカーソルを合わせると、各チェックの結果が表示されます。
