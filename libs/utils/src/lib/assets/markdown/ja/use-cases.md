# ユースケース

トラッキングの問題は、多くの場合まず Google Analytics に現れます。ページビューが減少したり、イベントのパラメータが `(not set)` と表示されたりします。原因はたいてい、`dataLayer` を変えてしまったサイトの変更か、タグを壊してしまった GTM の変更です。TagCheck は、計画したすべてのイベントをサイトそのものでチェックすることで、こうした問題を見つけます。

TagCheck は次のような場合に適しています。

- タグが多いサイト、または GTM の設定を大幅にカスタマイズしているサイト。
- サイトのリリースや GTM の変更を頻繁に行うチーム。
- イベントに含まれるアイテムや値が常に正確でなければならない e コマースサイト。

## リリース後にすべてのイベントをチェックする

GTM コンテナをインポートして GA4 イベントタグごとに 1 つのテストを作成し、それぞれに記録を追加して、リリースのたびにすべて実行します。テスト一覧のテーブルでどのイベントが合格しなくなったかがわかり、Reports ページには比較用にすべての実行が残ります。

## 公開前にワークスペースをチェックする

Accompanied Mode ではテストを GTM Preview 経由で実行するため、テスト対象のタグは未公開のワークスペースのタグになります。TagCheck がデータレイヤーとリクエストをチェックしている間に、Tag Assistant でタグが発火する様子を確認できます。

## イベントだけでなくパラメータもチェックする

スペックには、イベントに必要なパラメータを、その値またはパターンとともに記述します。たとえば次のスペックは、単一のアイテムが Switzerland または California で、記載された価格と数量である `add_to_cart` プッシュを求めます。

```json
{
  "event": "add_to_cart",
  "ecommerce": {
    "currency": "USD",
    "value": 200,
    "items": [
      {
        "item_id": "$item_id",
        "item_name": "/^(?:Switzerland|California)$/",
        "item_category": "Europe",
        "quantity": 1,
        "price": 200
      }
    ]
  }
}
```

- `"$item_id"` は、値に関係なく `item_id` が存在することだけを求めます。
- `"/^(?:Switzerland|California)$/"` は、`item_name` がスラッシュで囲まれた正規表現に一致することを求めます。
- `"Europe"`、`1`、`200` は型も含めて完全に一致する必要があります。数値の `200` は文字列の `"200"` とは一致しません。

すべてのルールは **品質保証** に記載しています。

## GA4 に届くまでに変わるデータを検出する

GTM Preview に表示されるのはタグが受け取った内容であり、GA4 が受け取る内容ではありません。タグがパラメータを落としたり、イベントを別の測定 ID に送信したり、配列を文字列に変えたりすることがあります。こうした場合でも、データレイヤーチェックは合格します。リクエストチェックは GA4 リクエストそのものをスペックと比較するため、このずれが見過ごされることなくテストは Partial になり、結果には確認用に生のリクエストが保存されます。
