# イントロダクション

TagCheck は、Google Tag Manager（GTM）の設定が計画どおりのデータを送信しているかをチェックします。Chrome でユーザージャーニーを再生し、`dataLayer` へのすべてのプッシュとそのイベントの GA4 リクエストを取得して、両方をスペック（期待するイベントとパラメータ）と比較します。

## TagCheck の構成

- **プロジェクト**（Project）: テスト対象となる 1 つの Web サイトと、その設定です。設定には、各実行の前に読み込む値（同意 Cookie など）、サインイン情報、GTM のプレビューリンク、ブラウザのオプションが含まれます。
- **テスト**（Test）: チェック対象となる 1 つの GA4 イベントです。テストには、期待する `dataLayer` プッシュである **スペック**（spec）と、そのイベントを発生させる Chrome Recorder のジャーニーである **記録**（recording）があります。
- **実行**（Run）: テストの記録を 1 回再生することです。各実行では 2 つのチェックを行います。
  - **データレイヤーチェック**（data layer check）: `dataLayer` にプッシュされたイベントがスペックと一致すること。
  - **リクエストチェック**（request check）: イベントの GA4 リクエストがプロジェクトの測定 ID に送信され、そのパラメータがスペックと一致すること。
- **結果**（Result）: 実行で判明した内容です。両方のチェック結果、取得した `dataLayer`、生のリクエスト、スクリーンショット、画面録画が含まれます。
- **ステータス**（Status）: 各テストには最新の実行のステータスが表示されます。両方のチェックに合格した場合は **Passed**、一方のみ合格した場合は **Partial**、どちらにも合格しなかった場合は **Failed**、初回の実行前は **Not run** です。リクエストチェックなし（Request Check がオフ）で行った実行は、データレイヤーチェックだけで Passed または Failed になります。

## 実行中に行われること

1. TagCheck は Puppeteer で Chrome を開き、プロジェクトのプリロード値を読み込んで、テストの記録を再生します。
2. `dataLayer` へのすべてのプッシュを取得し、ページが送信する GA4 リクエストを傍受します。
3. イベントとリクエストをスペックと比較し、スクリーンショットと画面録画とともに結果を保存して、テストのステータスを更新します。

Accompanied Mode では、実行時に GTM Preview（Tag Assistant）経由でサイトを開くため、未公開のワークスペースでタグが発火する様子もあわせて確認できます。

## このドキュメントの内容

- **目的**: 2 つのチェックで検出できる問題。
- **ユースケース**: TagCheck が役立つ場面。
- **クイックスタート**: プロジェクトを作成し、テストを追加して実行する方法。
- **品質保証**: スペックの書き方とチェック結果の読み方。
- **レポート管理**: 結果、Reports ページ、スプレッドシート。
- **設定の詳細**: プロジェクトのすべての設定。
