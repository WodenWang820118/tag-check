# 品質保証

テストは、サイトと GTM がスペックに記述された内容を送信したときに合格します。このページでは、スペックの書き方、2 つのチェックがスペックとどのように比較するか、そしてタグを公開する前にレビューする方法を説明します。

## スペックの書き方

スペックは、期待する `dataLayer` プッシュを JSON で記述したものです。`event` で GA4 イベントを指定し、それ以外のキーはすべてプッシュに含まれていなければならないパラメータです。スペックに記載されていないキーは無視されるため、スペックには必要なパラメータだけを書けば十分です。

値は次のルールに従います。

| スペックの値                                | 合格する条件                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| `"$name"`（例: `"$item_id"`）               | 値に関係なく、キーが存在する                                            |
| `"{{Variable Name}}"`（Tag Manager の変数） | 値に関係なく、キーが存在する                                            |
| `"/pattern/"`                               | 値が、スラッシュで囲まれた正規表現に一致する文字列である                |
| その他の文字列、数値、ブール値              | 値が型も含めて完全に一致する                                            |
| オブジェクト（例: `ecommerce`）             | 同じルールで、そのすべてのキーが合格する                                |
| 配列（例: `items`）                         | 各要素が、実際の配列の少なくとも 1 つの要素と一致する（順序は問わない） |

例:

```json
{
  "event": "add_to_cart",
  "ecommerce": {
    "currency": "USD",
    "value": "$value",
    "items": [
      {
        "item_id": "$item_id",
        "item_name": "/^(?:Switzerland|California)$/",
        "quantity": 1
      }
    ]
  }
}
```

数値の `1` は文字列の `"1"` と一致しません。サイトが数値をプッシュする場合は、数値として記述してください。

GTM コンテナからインポートしたテストには、最初からタグをもとに作成されたスペックが設定されています。データレイヤー変数を読み取る各パラメータは、`"value": "{{DLV - ecommerce.value}}"` のように変数の参照を値に持つキーになるため、そのキーが存在する必要があります。より厳密にチェックしたい箇所では、参照を値またはパターンに置き換えてください。スペックを編集するには、テストを開いて **Latest result** に移動し、**Data Layer Spec** パネルの編集ボタンを使います。

## e コマースイベント

Google が推奨する e コマースイベント、および `ecommerce.items` を含むすべてのスペックでは、データレイヤーチェックはイベントの前に `{ ecommerce: null }` のプッシュがあることも求めます。これは、以前の e コマースデータをクリアするために Google が推奨しているものです（[Tag Manager で e コマースを測定する](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce?client_type=gtm)）。このリセットはブラウザの外に送信されないため、リクエストチェックではこのルールを適用しません。

テストには **Item Definition** を設定することもできます。これは、次のような 1 つの GA4 アイテムです。

```json
{
  "item_id": "city001",
  "item_name": "Switzerland",
  "item_category": "Switzerland",
  "quantity": 1,
  "price": 799
}
```

この場合、e コマースイベントの実行では、スペック内のアイテムの代わりに、このアイテムが `ecommerce.items` の要素として期待されます。編集は、テストの **Latest result** にある **Item Definition** パネルで行います。

## リクエストチェック

**Activate Request Check** がオンの場合、TagCheck はプロジェクトの測定 ID に送信された、テストのイベントの GA4 リクエストを傍受します。リクエストからイベント名、イベントパラメータ、アイテムを読み取り、`dataLayer` プッシュと同じ形のオブジェクトに再構成してから、同じスペックを適用します。Google はこのリクエストの形式をドキュメント化していないため、TagCheck は gtag.js が送信するとおりの形式で読み取ります。

再構成されたオブジェクトは、リクエストに含まれる型を保持します。数値のイベントパラメータ（`epn.`）と、`price` や `quantity` などの数値のアイテムフィールドは数値になり、その他のイベントパラメータ（`ep.`）は文字列のままです。タグが数値をテキストパラメータとして送信している場合、スペックの値 `200` はデータレイヤーチェックには合格しますが、リクエストチェックでは `"200"` に対して失敗します。タグを修正するか、型が重要でない箇所では `"$value"` やパターンを使ってください。

## タグのレビュー

テストの **Tag Snapshot** タブには、テストの作成元となった GA4 イベントタグが表示されます。

- **Measurement ID**: タグの送信先となる ID です。タグが `{{CONST - Measurement ID}}` のような定数変数を参照している場合、タブには定数の値が表示され、その下に参照が表示されます。
- **Event Name** と **Event Parameters**: タグが送信するパラメータです。タグのイベント設定変数から送信されるものも含まれます。データレイヤー変数を読み取る値には、`Data layer: ecommerce.value` のように、読み取るデータレイヤーのキーが表示されます。
- **Triggering**: タグのトリガーです。

これをスペックと比較して、サイトがプッシュするキーをタグが読み取っているかを確認します。

## Accompanied Mode

Accompanied Mode ではテストを GTM Preview 経由で実行するため、テスト対象のタグは、未公開であってもプレビューしているワークスペースのタグになります。使用するには、**Google Tag Manager** 設定で **Preview Mode URL** を入力し、**Activate Accompanied Mode** をオンにします。実行するとサイトの隣に Tag Assistant が開き、確認のために実行後もブラウザウィンドウは開いたままになります。確認が終わったらウィンドウを閉じてください。
