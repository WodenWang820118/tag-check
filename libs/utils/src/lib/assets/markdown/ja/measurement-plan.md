# 測定プラン

測定プランは、Web サイトで収集すべきイベントとパラメータを定義するものです。TagCheck において測定プランは、デジタルマーケティングチームと開発チームをつなぐ共通の設計書となります。Tag Build がこれを Google タグマネージャー（GTM）コンテナに変換し、Web 開発者が対応する `dataLayer.push` を実装し、TagCheck がサイトが正しいデータを送信しているかを検証します。

## イベントの分類と命名規則

イベント追跡を設計する際は、各ユーザー操作が Google の推奨イベントに該当するか、カスタムイベントが必要かを判断します。

### 推奨イベントとカスタムイベント

- **[Google の推奨イベント](https://developers.google.com/analytics/devguides/collection/ga4/reference/events?client_type=gtm)**: Google は、オンライン販売、リード獲得、ゲームなどの主要な業種ごとに標準のイベント名とパラメータ名を定義しています。`purchase`、`add_to_cart`、`sign_up`、`generate_lead` などの推奨名を使用することで、GA4 の組み込みディメンション、指標、および e コマースファネルレポートが自動的に有効になります。
- **カスタムイベント**: 推奨リストに該当しない独自の操作（インタラクティブな計算ツールの利用や特殊な絞り込みの選択など）には、カスタムイベント名を定義します。カスタムイベントのパラメータ値を標準レポートで確認するには、GA4 でカスタムディメンションまたはカスタム指標を登録する必要があります。

### イベント名とパラメータ名の命名規則

Google アナリティクス 4 では、イベント名およびパラメータ名に厳密な[命名規則](https://support.google.com/analytics/answer/13316687)が適用されます。

- **使用可能な文字**: イベント名およびパラメータ名は英字で始まり、英字、数字、アンダースコア（`_`）のみを使用できます。スペース、ハイフン、ピリオドは使用できません。
- **文字数制限**: イベント名およびパラメータ名は最大 40 文字です。
- **大文字と小文字の区別**: イベント名は大文字と小文字を区別します（`Purchase` と `purchase` は別々のイベントとして扱われるため、通常は小文字の `purchase` を使用します）。
- **予約済みの接頭辞と単語**: パラメータ名は `firebase_`、`ga_`、`google_` で始めることはできません。また、`event` はデータレイヤーの予約語であるため、イベントパラメータ名としては使用できません。

## プランの 1 行から TagCheck の検証まで

測定プランの各行は、以下の 5 段階のライフサイクルを経て検証されます（`purchase` イベントの例）：

1. **プランの 1 行**: CSV 内でイベントと期待されるパラメータを定義します。
   - `event_name`: `purchase`
   - `event_parameters`: `transaction_id=/^T\d+$/, currency=TWD, value`
   - `item_parameters`: `item_id, item_name, price`
2. **サイトが送信する `dataLayer.push`**: Web サイトの開発者が `window.dataLayer` にイベントと e コマースデータをプッシュします。e コマースイベントでは、直前の `ecommerce` オブジェクトをあらかじめクリアします。
   ```javascript
   window.dataLayer = window.dataLayer || [];
   window.dataLayer.push({ ecommerce: null }); // clear the previous ecommerce object
   window.dataLayer.push({
     event: 'purchase',
     ecommerce: {
       transaction_id: 'T12345',
       currency: 'TWD',
       value: 1200,
       items: [{ item_id: 'SKU_123', item_name: 'Example', price: 1200 }]
     }
   });
   ```
3. **Tag Build が生成する GTM タグ**: Tag Build はプランをカスタムイベント `purchase` でトリガーされる GA4 イベントタグに変換します。e コマースイベントでは、タグはデータレイヤーの `ecommerce` オブジェクトから自動的にデータを読み取ります。
4. **GA4 が受信する内容**: ブラウザでタグが配信されると、GTM は測定 ID（`&tid=...`）、イベント名（`&en=purchase`）、イベントパラメータ（`&ep.currency=TWD`）、およびアイテムパラメータを含む HTTP `/g/collect` リクエストを Google アナリティクスに送信します。
5. **TagCheck が検証する内容**: Puppeteer でユーザージャーニーを再生し、TagCheck は 2 つのチェックを実行します。
   - **データレイヤーチェック**: 取得した `dataLayer.push` のペイロードをプランのスペックと比較し、`transaction_id` が正規表現 `/^T\d+$/` に一致すること、`currency` が `'TWD'` であること、`value` が存在すること、`items` に必要なプロパティが含まれていることを確認します。
   - **リクエストチェック**: GA4 への送信ネットワークリクエストをインターセプトし、`/g/collect` が指定された測定 ID に期待通りのイベント内容で届いているかを検証します。

## ルール構文

測定プランの各パラメータには検証ルールを定義できます。TagCheck はテストの再生時にこれらのルールを評価します。

| ルール形式   | 例                           | プラン構文                                  | TagCheck が判定する条件                                                                                                                                  |
| :----------- | :--------------------------- | :------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **任意の値** | `currency` や `value`        | パラメータ名のみ（スペック: `"$currency"`） | データレイヤーのプッシュ内に該当のキーが存在することのみを要求します。任意の値（文字列、数値、真偽値）で合格となります。                                 |
| **特定の値** | `currency=TWD` や `value=10` | パラメータ名の後に `=<値>`                  | プッシュされた値が期待値と厳密に一致（`===`）することを要求します。`value=10` は数値、`in_stock=true` は真偽値、`level="10"` は文字列を求めます。        |
| **正規表現** | `transaction_id=/^T\d+$/`    | パラメータ名の後に `=/<パターン>/[フラグ]`  | プッシュされた値が文字列であり、正規表現パターンに一致することを要求します。フラグ（`i` など）に対応しており、パターン内にカンマを含めることも可能です。 |

`ecommerce.items` などの配列を検証する場合、TagCheck はスペックで定義されたすべてのエントリが、実際の配列内の少なくとも 1 つのエントリと（順不同で）一致することを要求します。

## 開発者への引き渡し: "For developers" スニペット

Web 開発者へのスムーズな引き渡しのため、Tag Build には **For developers** ボタンが用意されています。

1. Tag Build にプランのスペックを入力またはアップロードします。
2. **For developers** をクリックして開発者向けスニペットダイアログを開きます。
3. Tag Build は各イベントのコピー可能な完全な JavaScript コードを生成します。
   - 推奨イベントには Google の公式ドキュメントアンカーへのリンクを記載。
   - e コマースイベントには `{ ecommerce: null }` の初期化コードを含める。
   - パラメータ名に応じた現実的なサンプル値を設定（通貨は `USD`、数値は `0`、アイテム ID は `SKU_123`、取引 ID は `T12345`）。
   - 各パラメータに検証ルールを説明するインラインコメントを付与（`// must match /^T\d+$/`、`// must be "TWD"`、`// any value`）。
4. **Copy all** または **Download (.js)** をクリックして、すべてのスニペットをエンジニアリングチーム向けの JavaScript ファイルとして保存します。

## TagCheck での流れ

TagCheck は Tag Build をテストワークフローに直接統合しています。

- **Import into this project**: TagCheck 内の TagBuild ページでプランの変換チェックに合格したら、**Import into this project** をクリックします。生成された GTM タグ、トリガー、変数が現在のプロジェクトの設定に直接インポートされます。
- **Use this project's container**: **Tag Extract** タブでは、プロジェクトに保存されているコンテナを読み込み、有効な GA4 タグを測定プラン CSV として逆抽出できます。抽出されたプランをダウンロードしてイベントルールを調整し、再度アップロードして追跡スペックをブラッシュアップできます。
