# 目標

TagCheck 的目標是在追蹤問題進入 Google Analytics 報表之前就把它們找出來。它會在實際網站上，以每次都相同的方式檢查每個規劃好的 GA4 事件，讓你可以在每次網站發布或 GTM 變更後重新執行這些檢查。

## 資料層檢查

網站會將資料推送到 `window.dataLayer`，GTM 則讀取這些資料來填入其代碼。資料層檢查會找出測試事件的那次推送，並將它與規格逐鍵比對。以下情況會判定為失敗：

- 事件從未被推送；
- 規格中的某個鍵不在推送中；
- 某個值與規格不同，或不符合其模式；
- 電子商務事件之前沒有先推送 `{ ecommerce: null }`。Google 要求進行這次推送，以清除先前的電子商務資料（[使用 Tag Manager 評估電子商務](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce?client_type=gtm)）。

## 請求檢查

正確的推送並不保證 GA4 中的資料正確。代碼可能沒有觸發、可能傳送到其他資源，也可能以 GA4 不會收集的形式傳送參數。請求檢查會查看實際離開瀏覽器的內容：它會攔截該事件傳送到專案評估 ID 的 GA4 請求，將請求參數重組成形狀類似 `dataLayer` 推送的物件，再將這個物件與同一份規格比對。如果沒有送出這樣的請求，或其參數不符，就會判定為失敗。

請求檢查需要在 **Project Information** 中填寫評估 ID，並在 **Google Tag Manager** 設定中開啟 **Activate Request Check**。沒有請求檢查時，執行只會進行資料層檢查：該次執行的請求檢查會顯示為 **Not checked**，狀態只依資料層檢查決定（Passed 或 Failed）。

## 解讀狀態

- **Passed**：兩項檢查都通過。
- **Partial**：一項檢查通過。網站可能推送了正確的資料，但代碼沒有依規劃送出；也可能正好相反。
- **Failed**：兩項檢查都未通過。請先從資料層著手：事件可能從未被推送。
- **Not run**：測試尚未有任何執行，或其所有執行都已被刪除。

將游標移到狀態上，即可查看每項檢查的結果。
