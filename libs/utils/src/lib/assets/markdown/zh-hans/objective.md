# 目标

TagCheck 旨在让追踪问题在进入 Google Analytics 报告之前就被发现。它在真实网站上检查每个规划好的 GA4 事件，每次都以相同的方式进行，因此您可以在每次网站发布或 GTM 变更之后重新运行这些检查。

## 数据层检查

网站将数据推送到 `window.dataLayer`，GTM 读取这些数据来填充其标签。数据层检查会找到测试事件对应的推送，并逐个键地与规格进行比较。出现以下情况时，检查失败：

- 该事件从未被推送；
- 规格中的某个键在推送中缺失；
- 某个值与规格不同，或与其模式不匹配；
- 电子商务事件之前没有先推送 `{ ecommerce: null }`。Google 要求进行此推送，以清除之前的电子商务数据（[使用 Tag Manager 衡量电子商务](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce?client_type=gtm)）。

## 请求检查

推送正确并不能保证 GA4 中的数据正确。标签可能没有触发，可能发送到了另一个媒体资源，也可能以 GA4 不会收集的形式发送参数。请求检查关注的是实际离开浏览器的内容：它拦截发送到项目测量 ID 的该事件的 GA4 请求，将其参数重建为一个结构与 `dataLayer` 推送相同的对象，并将该对象与同一规格进行比较。如果没有发送此类请求，或者请求的参数不匹配，检查失败。

请求检查需要在 **Project Information** 中填写测量 ID，并在 **Google Tag Manager** 设置中开启 **Activate Request Check**。否则，运行只会进行数据层检查：该次运行的请求检查显示为 **Not checked**，状态只由数据层检查决定（Passed 或 Failed）。

## 解读状态

- **Passed**：两项检查都通过。
- **Partial**：一项检查通过。可能是网站推送了正确的数据，但标签没有按计划发送；也可能正好相反。
- **Failed**：两项检查都未通过。请先从数据层查起：该事件可能从未被推送。
- **Not run**：测试尚未运行，或其所有运行都已被删除。

将鼠标悬停在状态上，即可查看每项检查的结果。
