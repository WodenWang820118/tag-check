# 介绍

TagCheck 用于检查 Google Tag Manager（GTM）配置是否发送了您规划的数据。它在 Chrome 中重放用户旅程，捕获每一次 `dataLayer` 推送以及该事件的 GA4 请求，并将两者与规格进行比较：规格即您期望的事件及其参数。

## TagCheck 的组织方式

- **项目**（Project）：一个被测网站及其设置，包括每次运行前要加载的值（例如用户同意 Cookie）、登录信息、GTM 预览链接和浏览器选项。
- **测试**（Test）：要检查的一个 GA4 事件。每个测试有一个**规格**（spec），即它期望的 `dataLayer` 推送；还有一个**录制**（recording），即触发该事件的 Chrome Recorder 用户旅程。
- **运行**（Run）：对测试录制的一次重放。每次运行会进行两项检查：
  - **数据层检查**（data layer check）：推送到 `dataLayer` 的事件与规格相符；
  - **请求检查**（request check）：该事件的 GA4 请求已发送到项目的测量 ID，且其参数与规格相符。
- **结果**（Result）：一次运行的发现，包括两项检查、捕获的 `dataLayer`、原始请求、一张截图和一段录屏。
- **状态**（Status）：每个测试显示其最近一次运行的状态：两项检查都通过时为 **Passed**，只有一项通过时为 **Partial**，两项都未通过时为 **Failed**，首次运行之前为 **Not run**。

## 运行期间会发生什么

1. TagCheck 通过 Puppeteer 打开 Chrome，加载项目的预加载值，然后重放测试的录制。
2. 它记录每一次 `dataLayer` 推送，并拦截页面发送的 GA4 请求。
3. 它将事件和请求与规格进行比较，保存结果以及截图和录屏，并更新测试的状态。

在伴随模式（Accompanied Mode）下，运行会通过 GTM 预览（Tag Assistant）打开网站，因此您还可以观察未发布工作区中的标签触发。

## 本文档内容

- **目标**：两项检查能发现哪些问题。
- **使用场景**：TagCheck 在哪些情况下能派上用场。
- **开始使用**：创建项目、添加测试并运行测试。
- **质量保证**：编写规格并解读检查结果。
- **报告管理**：结果、Reports 页面和电子表格。
- **设置详情**：所有项目设置。
