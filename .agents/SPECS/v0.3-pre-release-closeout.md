# Capture Workbench v0.3 Pre-release Closeout

## Purpose

Prepare one synchronized `0.3.4` candidate for the public Angular/Web
Component package, Windows x64 Capture Runtime assets, and Windows NSIS desktop
installer. The candidate must be locally reproducible, consumer-tested, and
publishable through a fail-closed draft release transaction.

`v0.3.0` is already a public GitHub Release and tag, and `v0.3.1` is occupied
by an externally created annotated tag whose workflow failed before producing a
candidate. The lightweight `v0.3.2` tag is also occupied: release run
`30517094297` failed before publication because Windows checkout converted the
canonical source-lock JSON to CRLF. None of these tags may be overwritten.
The lightweight `v0.3.3` tag is occupied at
`cfe570474a6925b4ad41a7c49685cae90f8aeebb`: release run `30523583549`
failed in the redundant pre-staging `pnpm verify` step because the clean
release environment intentionally had not staged the Tauri sidecar or installed
the optional `pypdfium2` and Pillow worker dependencies. Publication was
skipped, and no GitHub Release, assets, or package were created. Preserve the
tag and run as immutable failure evidence.
GitHub Packages state could not be read anonymously because the registry
returned `E401`; all code therefore treats an existing `0.3.4` with different
bytes as a permanent conflict.

This specification expands and supersedes the narrower release and desktop
non-goals in `release-publication-v1.md` and
`standalone-desktop-hardening.md`. Those files remain historical evidence.

## Non-Goals

- Do not create a tag, publish a package, create or publish a GitHub Release,
  change organization settings, or edit `cert-prep`.
- Do not change the Observable-first public API, `CaptureClient`,
  `CaptureStructuringProvider`, `CapturePreprocessor`, `CaptureDocumentV1`,
  Runtime API major/schema handshake, or bearer-token ownership.
- Do not collapse deterministic, runtime, desktop, or packed-consumer test
  boundaries.
- Do not expose or persist sidecar tokens or complete local source paths.

## Interfaces

### Version and repository identity

- Angular package, Python runtime, Runtime constant, Cargo crate, and Tauri app
  use `0.3.4`.
- The exact checked-in canonical release source lock is forced to LF by a
  narrow root `.gitattributes` rule. CI and the tag workflow classify those
  checkout bytes before publication work.
- Public repository, schema, release, badge, and source links use
  `https://github.com/gx-capture/capture-workbench`.
- The authoritative schema keeps schema version `1`, but organization migration
  regenerates all exact schema bytes and SHA-256 constants.
- Because no public installer was present in the public `v0.3.0` release, the
  Tauri identifier becomes `io.github.gx-capture.capture-workbench`.

### Angular and Web Component package

- Direct Angular templates keep the `gx-capture-workbench` selector.
- Framework-neutral hosts call `defineCaptureWorkbenchElement()` and use
  `<capture-workbench>`.
- `@angular/elements` remains an internal regular dependency pinned to
  `22.0.7`; `@angular/forms` is a `^22.0.0` peer dependency.
- The main Workbench component uses Shadow DOM, retains its documented CSS
  custom properties, and cannot style host-page sentinels.
- Custom-element registration uses a `Symbol.for(...)` global registry, a
  branded constructor, failure eviction, and race-loser application cleanup.

### Packed consumers

- The packed tarball is installed into isolated Angular, Vanilla, React, and
  Vue fixtures.
- The Angular Web Component fixture uses `CUSTOM_ELEMENTS_SCHEMA`, does not
  import `@angular/elements` or the package component, waits for registration,
  assigns a fake client/config by property, and observes a custom event.
- Browser smoke runs each framework on a random port, proves mount/property/
  event behavior, and always terminates preview processes and removes the
  temporary fixture.

### Release publisher and CI

- The publisher accepts `--tag`, `--runtime-dir`, `--installer`, and
  `--package`.
- Local preflight proves the exact regular-file candidate, canonical runtime
  assets, manifest/schema/checksum consistency, unique NSIS installer, tarball
  identity, version, contents, and integrity before the first remote write.
- A missing release is created as a draft. Draft assets are uploaded and
  downloaded for exact size/SHA-256 verification. The package is then published
  or proved byte-identical. Only after a second complete asset verification is
  the release made public.
- Public releases are read-only: exact assets/package are idempotent success;
  missing or different bytes fail closed.
- CI runs for `main`, `develop`, and pull requests. A release tag must be an
  ancestor of `origin/main` before dependency installation or production work.
- Pull-request and `main` CI own the complete workspace
  lint/typecheck/test/build/package/desktop/smoke proof. The release workflow
  consumes one successful exact-commit `main` push CI run for the tagged SHA;
  it does not rerun the redundant full-workspace `pnpm verify`.
- After exact-main proof, release retains frozen dependency installation,
  synchronized-version validation, canonical source-lock classification,
  model receipt/catalog rules, production release-artifact rebuilding, runtime
  staging, NSIS building, installed-size/budget checks, candidate
  assembly/upload, and fail-closed publication.
- A real temporary Git repository configured with `core.autocrlf=true` must
  check out the actual `.gitattributes` and source-lock bytes as LF and
  successfully classify them without weakening canonical byte validation.
- Organization branch protection and package visibility remain explicit manual
  gates.

### Desktop persistence and deletion

- A library update constructs an immutable next document/index and stages raw,
  result, and index bytes before committed replacements.
- `library-transaction-v1.json` records transaction ID, document ID, operation,
  temporary/backup file names, target index version, and stage. `open()` either
  completes or rolls back an interrupted transaction.
- Failure injection covers temporary writes, replacements, cleanup, and reopen
  recovery without allowing disk/in-memory divergence.
- A document with an active renderer capture or retained runtime `captureId`
  cannot be directly deleted. The UI disables deletion while busy and tells the
  user to cancel first. Native deletion rejects records retaining a capture ID.

### Native source import

- Tauri 2 native path support is used: the official dialog plugin returns
  selected paths, while core `onDragDropEvent` provides dropped paths. The
  renderer sends paths only to the private native import command and never
  receives them back.
- Rust checks `symlink_metadata`, rejects symlinks/directories/special files,
  canonicalizes the source, checks metadata size before opening, performs a
  bounded read, verifies final length and magic signature/MIME, and copies into
  the app-owned library before capture starts.
- The response, summaries, exports, diagnostics, and QA evidence contain only
  the sanitized base file name and opaque document ID.
- Exactly 50 MiB is accepted when its signature is valid; 50 MiB plus one byte
  is rejected before a complete read.

## Edge Cases and Failure Modes

- An occupied custom-element tag owned by another constructor is a clear
  conflict. A failed registration is retryable. A registration race destroys
  the application created by the loser.
- Draft asset upload, package publication, or release-publication failure leaves
  the release draft. A later identical run resumes safely.
- An existing package, runtime asset, schema, tarball, or installer with
  different bytes is never overwritten.
- Library journal cleanup failure leaves a recoverable committed journal; open
  must not ignore it.
- Source import errors are redacted and cannot include the full input path.

## Acceptance Criteria

- All Phase 0 owner/version/schema/identifier migrations are synchronized.
- Packed manifest and browser consumers prove Angular and Web Component
  contracts, Shadow DOM isolation, event semantics, and framework mounts.
- Publisher state-matrix tests prove missing/draft/public and
  missing/same/different package/asset states plus retry failures.
- CI includes `develop`; release ancestry and exact-main-CI proof run early;
  the release candidate is rebuilt through the release-specific reproducibility
  and integrity gates and includes runtime, schema, tarball, and NSIS installer.
- Fresh Windows-style checkout proof preserves canonical LF source-lock bytes,
  and CI classifies them before the longer package/runtime lanes.
- Library failure/restart tests and active-delete tests pass.
- Renderer source import contains no `Array.from(new Uint8Array(...))` or
  source-byte JSON IPC.
- The checked-in release checklist distinguishes automated, unavailable, and
  manual gates honestly.
