# Tag Check 3.5.0

Tag Check 3.5.0 introduces parameter validation rules to measurement
plans, carrying exact values and regular expressions through GTM into
test specs. Tag Build and Tag Extract connect directly to your project,
and re-importing a container matches tests by tag name to avoid
duplicates. Measurement plans now provide developer code snippets and
in-app guidance, while project transfers and concurrent operations are
hardened against data loss.

## Highlights

- Re-importing a GTM container matches tests by tag name rather than
  creating duplicates. When a tag's GA4 event name changes, Tag Check
  asks whether to update the existing test—preserving its recording,
  item definition and run history—or keep both tests. (#593)
- Tag Build and Tag Extract connect directly to the active project. You
  can import a newly converted container straight into your project
  without downloading and re-uploading, or load the project's container
  into Tag Extract with one click. Conversions display generated counts
  of tags, triggers and variables, and common notes are grouped cleanly
  above the table. (#595)
- Measurement plans can define validation rules directly in parameter
  cells: require any value (`currency`), an exact match
  (`currency=TWD`, `value=10`, `in_stock=true`), or a regular
  expression pattern (`transaction_id=/^T\d+$/`). Rules are stored in
  GTM tag notes, applied to Tag Check test specs on import, and
  preserved when exporting back to a plan CSV. (#596)
- Tag Build explains measurement plans right when you create or upload
  them. A developer dialog provides copyable, ready-to-use
  `dataLayer.push` snippets for every planned event with rule comments
  and ecommerce resets. In-app guidance and a downloadable template
  demonstrate each rule syntax, supported by a dedicated Measurement
  plan guide in the documentation. (#597)

## Changes

### Runs and results

- **Run again** on the latest run opens the new run immediately
  (`?run=<id>`), updating the verdict, video and history. It uses the
  Tests page's headless setting, and runs started before project
  settings finish loading no longer force headful mode. (#591)
- Opening a link to a deleted or unknown run shows "Run not found"
  while keeping the run history and linking to the latest run, instead
  of claiming the test never ran. (#591)
- Older runs display a notice that they are compared against the
  current spec and recording. Spreadsheet exports from an older run
  include only that run's data. (#591)
- Step fallback badges ("Saved in the recording") are checked against
  the test's actual recording and refresh after saving. (#591)
- Re-saving recorded steps restores the previous steps and title if
  writing the recording file to disk fails. (#592)
- Importing a GTM container skips paused GA4 event tags with the reason
  "Paused", avoiding tests that cannot pass. (#592)
- The GA4 request check handles event names matching built-in property
  names such as `constructor` or `toString` without failing. (#590)

### Tag Build and Tag Extract

- Tag Build clears previous conversion output whenever the input is
  uploaded, pasted, or edited, preventing accidental downloads of stale
  containers. (#594)
- Parameters with empty string values (`""`) are kept in the plan and
  container rather than dropped. (#590)
- Measurement plans reject parameter rows named `event` with a helpful
  message, protecting the data layer event key. (#590)
- Event names matching built-in property names (such as `constructor`,
  `toString` or `valueOf`) no longer crash Tag Extract or misplace
  parameters in Tag Build. (#590)
- Measurement plan CSV parsing reports the starting line number for
  formatting issues such as unterminated quotes, duplicate required
  headers, or mismatched row widths. (#590)
- GTM tags defining parameters in both `eventParameters` and
  `eventSettingsTable` merge both tables by parameter name, noting any
  conflicts. (#590)
- Tag Extract lists unanchored, wildcard or negated regex triggers, as
  well as tags without firing triggers, as skipped with a reason
  instead of dropping them silently. (#590)
- Downloaded containers are named with the local date
  (`gtm-container-YYYY-MM-DD.json`), prefixed with the project slug in
  Tag Check. (#594)
- Spreadsheet read errors show the underlying error message cleanly
  without duplicate "Error:" prefixes. (#594)

### Projects and storage

- Runs, batches, schedules and imports no longer interfere when they
  write to the database at the same time, and a failed import no longer
  undoes a run result saved in the meantime. (#599)
- Project imports validate the fixture in staging before touching the
  existing project folder, and restore the previous folder if the import
  fails. Mismatched project file names are rejected, and concurrent
  uploads and exports use their own temporary folders. Deleting a
  project whose folder cannot be removed now fails and keeps the
  project, instead of reporting success. (#589)
- On Windows, importing a project retries renaming a folder while a file
  inside it is still open (for example, while antivirus scans it), so a
  failed import restores the previous project folder. (#600)
- Saving pre-loading values saves the Website URL alongside cookies and
  localStorage, and rejects non-HTTP URLs. (#591)

### Interface

- In Tag Check, opening the Conversion Successful dialog no longer
  scrolls the page or moves tabs out of view. (#594)
- The Custom Events developer article in the standalone site appears
  only on the Tag Build tab. (#594)
- Documentation links keep the active language when following
  redirects to the application documentation. (#592)

## Upgrading

Install 3.5.0 over 3.4.0. The database, projects, Tests and Runs are
kept. Existing measurement plans and GTM container exports continue to
work as before.
