# Tag Check 2.2.0

Tag Check 2.2.0 makes GA4 request capture reliable, including in GTM preview
mode, validates GA4 events against Google's rules, and imports more of a GTM
container export. It also fixes the report, settings and navigation problems
found while walking through the app before this release. The example project
now replays against the redesigned demo storefront.

## Highlights

- GA4 requests are captured through the page's Fetch domain. Events that
  gtag.js batches into one request, moves into the POST body, or sends as a
  keepalive request when a click leaves the page are now all found. When no
  request matches, the log lists the GA4 events that were seen.
- Inspections apply the project's localStorage preset again. A build issue
  had kept it from being written, so sites that load GTM only after stored
  consent never sent GA4 requests.
- GTM preview inspections work on consent-gated sites: the preset is written
  before Tag Assistant opens the site, and clicks pass through Tag
  Assistant's badge. A failed headless run no longer hangs the request.
- Validation follows Google's GA4 documentation: nested ecommerce objects and
  item arrays are compared field by field, item numbers must be numbers, GTM
  variables in a spec only require the value to be present, and event names
  that break GA4 naming rules are reported.
- Importing a GTM container export resolves Data Layer Variables to their
  dataLayer paths. Importing again refreshes generated specs and keeps edited
  ones.
- Data layer snapshots keep pushes that contain functions or page elements,
  such as GTM preview commands and `gtm.element`.
- The example project clicks stable `data-testid` hooks on the demo site.
  Existing installs get their shipped example recordings replaced at startup;
  recordings you edited are left alone.

## Fixes

- Reports show the run's screenshot and recording again. Neither had loaded
  since the move to Angular 22. Recordings now show their length and can be
  scrubbed. The media of a run appears as soon as it finishes, and a re-run
  shows its own screenshot instead of the first one.
- Pre-loading Values keeps what you type. Saving no longer wraps values such
  as `true` in quotes, which stopped consent-gated sites from loading GTM.
- A test that has never run shows **Not run** instead of a red **Failed**. A
  test in progress shows **Running**, and its progress chart shows a spinner
  until the steps are known.
- On wide screens the project menu stays beside the tests instead of
  covering them. The Settings submenu opens on click and closes when you
  click elsewhere or press Escape.
- Checked checkboxes use the primary color instead of a pale brown that
  looked disabled. Long TagBuild panel titles wrap, Reports shows a message
  when there are no runs yet, and row checkboxes and media controls have
  screen reader labels.

## Operator Notes

- The example project replays against https://ng-gtm-sample.vercel.app, which
  is deployed from `main` together with this release. Its home page now reads
  like a travel site; the `data-testid` hooks, page title and meta tags the
  recordings and SEO checks rely on are unchanged.
- TagCheck's own screens carry `data-testid` hooks along the user journey,
  named area first in kebab-case, with the GA4 event name or project slug as
  the per-row suffix (for example `run-test-add_to_cart`).
- Run `pnpm run version:sync` after changing any release version authority.
- Run `pnpm run version:check` or `pnpm run tauri:release -- describe` before
  pushing a release PR.
- Add `docs/releases/<version>.md` whenever the checked-in `VERSION` advances.
