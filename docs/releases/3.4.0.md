# Tag Check 3.4.0

Tag Check 3.4.0 redesigns a test's page around the run's verdict and
replays Chrome Recorder recordings more faithfully. When a step cannot
find its element, a run can continue with the one element that clearly
matches the recording, and an optional model on your computer can
suggest a replacement. Tag Build can extract a measurement plan from a
GTM container.

## Highlights

- A test's page opens on the run's verdict: both checks, the run
  history and a message for each. The site and Tag Assistant recordings
  play together on one timeline with the recorded steps; select a step
  to play from just before it. The spec is compared with the captured
  `dataLayer` push, and the GA4 request is shown as a table. Any earlier
  run can be opened. (#576, #577, #578)
- Each run keeps its own screen recordings; a test's latest 10 runs keep
  theirs. (#576)
- Replays follow what Chrome Recorder records: selector chains into
  shadow roots, steps inside iframes, and the page a step navigates to.
  (#583)
- When none of a step's selectors matches, the run looks for exactly one
  element with the recorded test hook, id or name and continues with it.
  The result says so, and the test's page offers to save that selector
  into the recording. (#584, #585)
- AI Assist (optional, off by default): with Ollama and a model on this
  computer, **Find a replacement** on a step that could not find its
  element suggests elements from what the run saw. A trial run checks a
  suggestion without changing the recording; you choose what to save.
  Page data never leaves the computer, and a suggestion never passes a
  test: the run's checks do. (#579, #580, #581, #582)
- Tag Build's **Tag Extract** tab reads a GTM container export and lists
  the GA4 events its tags send as measurement plan rows, to download as
  CSV or open in Tag Build. (#573)

## Changes

### Runs and results

- A run that stops at a step names the step and why, such as "Step 5
  (click) could not find its element". (#580)
- Before saving new selectors into a step, each can be unticked, for
  example a long structural path. (#586)
- The screen recording no longer falls seconds behind the run during
  page animations. (#576)
- Each run keeps the GA4 request check's message. (#576)

### Interface

- Small text is sized for the app's 10px root and no longer renders
  below 12px; the duplicate Material theme is gone and the initial
  downloads are smaller. (#574, #575)
- The docs recommend recording with `data-testid` as Chrome Recorder's
  selector attribute, and explain fallbacks and AI Assist. (#582, #585)

### Platform

- The backend end-to-end tests run on their own database. (#572)

## Upgrading

Install 3.4.0 over 3.3.0. The database, projects, Tests and Runs are
kept; runs gain columns for their own recordings and step times. Runs
made before 3.4.0 keep their screenshots; only the latest one keeps its
screen recording.

AI Assist needs [Ollama](https://ollama.com) running on this computer and
a model (`qwen3.5:9b` by default). Tag Check does not install either;
**Settings › AI Assist** shows the `ollama pull` command to run.
