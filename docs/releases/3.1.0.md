# Tag Check 3.1.0

Tag Check 3.1.0 is the release after 3.0.0. It brings faster reports,
Run deletion, a database that upgrades through migrations, rewritten
documentation in English, Japanese, Simplified Chinese and Traditional
Chinese, and UI fixes.

## Highlights

- Reports and spreadsheet exports load less data and open faster. (#506, #514)
- Delete Runs and their screenshots from the Reports page, keeping the Tests. (#518)
- Tests and Runs show one status chip: Passed, Partial, Failed, Not run or
  Running. Its tooltip lists both checks. (#512)
- Tag Snapshot resolves Constants and Data Layer Variables and includes
  parameters from the tag's Event Settings variable. (#516)
- The navigation bookmark now saves and affects replay's last click. (#524)
- Existing databases upgrade through migrations, keeping their data. (#521)
- All seven product documentation pages are rewritten in four languages
  for the current app. (#520)

## Changes

### Reports and results

- The Reports page lists one Run per row, newest first, with each Run's own
  time. Opening a project without Runs clears the previous rows. (#506)
- Deleting rows removes them only after server confirmation. Deleting the
  latest Run restores the previous Result; deleting every Run leaves the
  Test as Not run, with no last-run time. (#518)
- Spreadsheet summaries use the latest Run's Passed, Partial, Failed or
  Not run status; they previously always showed Failed. Downloads list
  each selected Test once and still include every Run's Result. (#506, #514)
- Long JSON panels scroll within 480px; Raw Request keeps its 300px limit. (#517)

### Tests and runs

- The Tests table's Last run and the Reports page's Run at columns use
  the Run's time rather than the Test's last update. (#518)
- Tag Snapshot shows a Constant's Measurement ID, the keys read by Data
  Layer Variables, and Event Settings parameters. Variables that need
  runtime evaluation are not resolved. (#516)
- The bookmark saves both enabling and disabling navigation blocking.
  Badges change only after success; a failed save keeps the previous state. (#524)
- A Run that stops before its checks finish now saves an error message
  instead of leaving the previous Run's message on the Test. (#518)

### Interface

- Narrow windows use an overlay project menu, and the Tests table scrolls
  sideways so its Run buttons remain accessible. (#511)
- Pre-loading Values fields have labels, remove buttons have accessible
  names, and each page has its own browser title. (#511)
- The menu highlights the current section, including directly opened
  settings pages. Authentication passwords have a show/hide button. (#513)
- Tag Snapshot uses read-only code blocks. Project export and deletion
  have separate sections. Tables default to 10 rows, keeping saved sizes. (#513)
- Empty Result panels explain what running a Test captures. TagBuild's
  unfinished tab is removed and its output placeholder is clearer. (#511)
- Actions read Add tests, Create tests and Stop the running test. The Test
  page's result tab is now Latest result. (#512, #520)

### Documentation

- Seven pages in the app and documentation site cover the current Tests,
  Runs, Results, checks, settings, exports and deletion in four languages. (#520)
- Examples use `"/pattern/"` for regular expressions, describe the supported
  recording selectors, and remove settings pages that no longer exist. (#520)

### Performance

- With two Runs, the Reports page response fell from 928,178 bytes to
  391 bytes by loading Run summaries without screenshots. (#506)
- On the same example data with 12 Tests, 21 Runs each and 30 MB of
  screenshots, median times over five requests improved as follows. (#514)

| Operation             | Before   | After  |
| --------------------- | -------- | ------ |
| Tests table           | 18 ms    | 6 ms   |
| Latest result detail  | 402 ms   | 10 ms  |
| Spreadsheet, 2 Tests  | 570 ms   | 44 ms  |
| Spreadsheet, 12 Tests | 2,045 ms | 198 ms |

- Project navigation makes one fewer API request by no longer loading
  every Test's recording. (#515)

### Under the hood

- Backend modules use OsModule and provide services once. (#507, #519, #522)
- Removed 22 unused packages, declared backend runtime dependencies
  explicitly, and moved the workspace to pnpm 12.14.0. (#508, #510)
- CI reports all unit-tested projects' coverage to SonarCloud and fixes
  the Storybook preview install. (#509)
- Firestore error reports omit undefined fields that caused rejection. (#523)

## Upgrading

An existing 3.0.0 database is synchronized once on its first start in 3.1.0.
The baseline migration is then recorded as applied; subsequent schema
upgrades use migrations. Existing data is kept. New databases are created
from the baseline migration. (#521)

The navigation bookmark only blocks native link and form navigation on
the recording's last click, which need not be its last step. Earlier
navigation is unchanged. Click handlers, dataLayer pushes and analytics
requests can still run. Single-page app routing and JavaScript navigation are
outside its scope. Turning the bookmark off restores normal navigation. (#524)

Deleting rows on the Reports page deletes Runs and their screenshots,
not Tests. Deleting a Test's latest Run also removes its screen recording:
each Run replaces that recording, so an older one cannot be restored. (#518)
