# Tag Check 3.6.0

Tag Check 3.6.0 lets you write a measurement plan inside Tag Build
instead of preparing a CSV elsewhere, and judges a run made without the
request check by its dataLayer check alone. The public web sites now
ship a Content Security Policy, and the workspace moves to Nx 24 with
updated dependencies.

## Highlights

- Tag Build has a **Write plan** dialog: a table with the plan CSV
  columns (`event_name`, `event_parameters`, `item_parameters`) and the
  same rule syntax (`currency`, `currency=TWD`,
  `transaction_id=/^T\d+$/`). Rows are checked as you type. **Use plan**
  writes the specs into the input, as a CSV upload does, and **Download
  CSV** saves a plan file that uploads again unchanged. (#603)
- A run made with Request Check off is judged by its dataLayer check
  alone. Before, every such run counted the request check as failed, so
  a run whose dataLayer check passed showed **Partial**. It now shows
  **Passed**, and the test page shows the GA4 request check as **Not
  checked**. (#611)
- The documentation site, the Tag Build site and the sample storefront
  ship a Content Security Policy, and every site sends shared security
  headers. (#630)
- A demo video walks through a whole project, from a new project to a
  passed run. It is linked from the README and served by the
  documentation site. (#613)

## Changes

### Runs and results

- The tests table, Reports, the test page verdict, run history, batch
  runs and the spreadsheet export all use the same rule for a run
  without the request check. The spreadsheet's request column reads
  "Not checked" for such a run. (#611)
- The status chip tooltip, the run snackbar and the selector trial
  result say "not checked" instead of reporting a failed request.
  (#611)
- Runs saved by earlier versions keep their status: they are read as
  runs that made the request check. (#611)

### Tag Build

- The Input JSON starts empty with a placeholder. In Tag Check, the Tag
  Build page no longer fills it with the project's specs. An empty
  input is not reported as a JSON error. (#603)
- Rows typed in **Write plan** are kept when the dialog is closed and
  opened again in the same session. (#603)

### Desktop installer

- On Windows, installing over an existing copy closes the running app
  and replaces the backend folder. Before, an upgrade could keep files
  the new backend no longer has. (#604)

### Web sites

- The documentation and Tag Build sites allow scripts only from the
  site itself, Google Tag Manager and inline scripts whose hash is in
  the page's policy. The sample storefront keeps scripts unrestricted,
  so any GTM container and Tag Assistant keep working on it. (#630)
- All sites send `frame-ancestors 'self'`, `X-Content-Type-Options`,
  `Referrer-Policy` and `Permissions-Policy` headers. (#630)

### Under the hood

- Nx 24, Puppeteer 25, Vitest 5, sqlite3 6, archiver 8 and other
  dependency updates. (#604)
- The Angular apps keep their state in signals and their forms in
  Signal Forms. Behaviour, saved settings and API calls are unchanged.
  (#605–#609)
- Unused code is removed, and a check stops new unused code from being
  added. (#614–#624)

## Upgrading

Install 3.6.0 over 3.5.0. The database, projects, Tests and Runs are
kept. The first start adds one column to the run results; no action is
needed.
