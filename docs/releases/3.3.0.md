# Tag Check 3.3.0

Tag Check 3.3.0 runs batches in the backend, so they keep going when the
window closes. It adds scheduled runs, a headless switch for every run,
and a desktop app that stays in the system tray with live progress and
notifications. GTM Preview connections are also more reliable.

## Highlights

- Batches run in the backend, one test at a time. Closing the window,
  reloading the page or restarting the app does not stop a batch; an
  interrupted batch resumes when the app starts again. (#566, #567)
- Schedule tests to run daily, weekly on chosen days, or every few hours,
  from **Schedule selected** on the Tests page. The new Schedules page
  shows each schedule's next and last run. Scheduled runs are headless;
  a run missed while Tag Check was closed is skipped. (#566, #567)
- **Run headless** on the Tests page applies to the play button and to
  Run selected, for direct and accompanied runs. The choice is kept per
  project. (#566, #567)
- Closing the desktop window keeps Tag Check running in the system tray.
  Use the tray icon to open the window again, or Quit from its menu. (#565)
- The tray shows the running test, its step and its place in the batch,
  in the tooltip and at the top of the tray menu. A system notification
  appears when a batch ends, and when a single run ends while the window
  is in the tray. (#568)

## Changes

### Runs

- Stop also stops batches; a batch can be cancelled and the tests it did
  not run resumed. (#566, #567)
- Accompanied runs wait for Tag Assistant's answer when GTM Preview
  connects and retry once when it cannot connect. Failures say so in
  plain words instead of a selector timeout. (#569)
- An accompanied run replays on the site's page, not on its service
  worker, after a retried connection. (#569)

### tag-build

- The site's initial download is about 110 kB smaller; it looks the same.
  (#562)

### Platform

- The tools, release and packaging scripts are type-checked and tested in
  CI. (#561, #564)
- Build configuration is ready for Nx 24. (#563)

## Upgrading

Install 3.3.0 over 3.2.0. The database, projects, Tests and Runs are
kept; the database gains tables for batch runs and schedules.

On Linux, the tray icon needs an AppIndicator-capable desktop; most
current desktops provide one.
