# Tag Check 3.0.0

Tag Check 3.0.0 is the first stable release. It builds on 2.2.0-preview:
reliable GA4 request capture, including in GTM preview mode; validation
against Google's GA4 rules; a fuller GTM container import; and the report,
settings and navigation fixes from the pre-release review. It also adds the
replay, import and report changes listed under
[Since 2.2.0-preview](#since-220-preview).

Earlier builds were published as alpha, beta and preview releases, up to
2.2.0-preview, plus a 2024 prerelease named 3.0.0-alpha. 3.0.0 is numbered
above all of them.

## What Tag Check does

- Import a GTM container export. Each GA4 event tag with a fixed, valid event
  name becomes a test with a `dataLayer` spec built from the tag's
  parameters. Tags whose event name is missing, set by a variable, or breaks
  GA4 naming rules are listed as skipped.
- Record the user journey for each test with Chrome Recorder. Tag Check
  replays it in Chromium, directly or through GTM Preview mode.
- Each run makes two checks: the site's `dataLayer` push against the spec, and
  a GA4 request for the test's event sent to the project's measurement ID.
- The report keeps the raw GA4 request, the captured `dataLayer`, a screenshot
  and a screen recording of the run. Reports export to a spreadsheet.
- TagBuild turns a `dataLayer` specification into a GTM container you can
  import.

## Highlights

These came in 2.2.0-preview; its release notes have the details.

- GA4 requests are captured even when gtag.js batches events, sends them in
  the POST body, or sends a keepalive request as a click leaves the page.
- GTM preview runs work on consent-gated sites.
- Validation follows Google's GA4 documentation, including nested ecommerce
  objects and item arrays.
- Reports show the run's screenshot and a recording you can scrub.
- Pre-loading Values are saved as typed. A test that has never run shows Not
  run, and a test in progress shows Running.

## Since 2.2.0-preview

- Click and change steps wait for whichever of the step's selectors appears
  first, under one timeout (the step's own timeout, or 15 seconds), instead
  of trying the selectors one after another.
- After a GTM container or GA4 event import, the tests table keeps each
  test's last result and recording state.
- A test's report page loads only the data it shows. It no longer downloads
  the project's report files with their screenshots, or the GTM
  configuration, so it opens faster.
- Run recordings no longer stop the server. Before, if the screen recorder's
  ffmpeg exited during a run, the backend exited with it ("write EOF"), and
  the desktop app could not run tests until restarted. Now the run continues
  without a recording and the reason is logged. Recordings are smaller
  (15 fps) and open with their length shown.
- The desktop app shows the run's screenshot in the report. Its content
  security policy blocked the screenshot image.
- The app, server and libraries are fully typed, and lint rejects `any`,
  non-null assertions and unused code. Behavior is unchanged.

## Desktop Assets

- Windows: `tag-check-desktop-v3.0.0-windows-x64-nsis.exe`
- macOS: `tag-check-desktop-v3.0.0-macos-arm64-unsigned.tar.gz`
- Linux: `tag-check-desktop-v3.0.0-linux-x64-appimage.AppImage`

The macOS build is for Apple silicon and is not signed. Expand the `.tar.gz`
and open the app inside. If macOS blocks it, allow it in System Settings >
Privacy & Security > Open Anyway. If macOS says the app is damaged, remove the
download quarantine and open it again:

```sh
xattr -dr com.apple.quarantine "Tag Check Desktop.app"
```

## Operator Notes

- Publish this release under the tag `v3.0.0`. The release workflow treats a
  version as released once it is published as `v<VERSION>`, `<VERSION>` or
  `v<VERSION>-preview`, and skips it from then on. Until then, the draft
  follows `main`: every code merge rebuilds its assets and rewrites its notes
  from this file. A merge that changes only documentation does not run the
  workflow, so edit the draft's notes by hand if only this file changed.
- The example project replays against https://ng-gtm-sample.vercel.app, which
  is deployed from `main` together with this release.
- Vercel deploys the four sites (ng-gtm-sample, TagBuild, the product
  documentation and Storybook) from `main` only. Pull requests into `develop`
  get previews of the sites they affect from the Vercel previews workflow,
  which needs the `VERCEL_TOKEN` repository secret.
- `pnpm run version:sync` writes the highest version found in `VERSION`,
  `package.json`, `tauri.conf.json` and `Cargo.toml` to all four. Update the
  `desktop-tauri` entry in `Cargo.lock` with it.
- Run `pnpm run version:check` or `pnpm run tauri:release describe` before
  pushing a release PR. (pnpm 11 passes a `--` separator through to the
  script, which then rejects it.)
- Add `docs/releases/<version>.md` whenever the checked-in `VERSION` advances.
